五分钟演示录屏脚本

录制前： 清空 Key 字段；关闭任何个人聊天/账号；将浏览器缩放为 100%；准备 Desktop 与 375px 两个窗口；确认当前素材均为演示数据。

时间 画面与操作 旁白重点
0:00-0:25 打开玩法工作台，停留在三栏全貌 “这是 LivePlay Lab：把互动 Brief 变成浏览器微应用，并把 Agent 质量放进可复跑评测。”
0:25-1:05 编辑主题、目标、受众、时长和边界 “我先写清时间、人力和不接真实平台数据这些边界；这一步避免生成器把假设当事实。”
1:05-1:35 切换三个模板，解释色条和规则 “我把玩法做成三套规则系统，而不是三段文案：拼图、真知题、接力赛各有不同参与动作和反馈。”
1:35-2:10 选择本地方案并生成 “默认不需要 Key。本地生成器输出规则、主持人口播、实现 Brief 和风险点，因此可用于快速原型讨论。”
2:10-2:45 点击微应用主按钮；切到真知题，再点击真/假 “右边不是静态卡片。作答会锁定，防止重复提交；这也是 Coding Agent 需要验证的状态要求。”
2:45-3:10 保存 Remix，到模板页刷新或载入 “可保留活动组织者改过的规则变体；只保存规则和来源，不保存密钥或用户信息。”
3:10-3:45 展示模型 API 弹窗，不输入真实 Key “支持任意 OpenAI-compatible API，但 Key 只保留在当前会话或本机 .env，并由本机代理调用。”
3:45-4:25 打开评测页、按分组筛选、标记一个人工复核 “50 条任务覆盖需求理解、代码生成、自验证、安全与体验。这里的复核标记不是通过率，真实模型运行后才有结论。”
4:25-4:50 打开用户研究页 “这里预留了 5 个访谈和 5 个无引导测试位置，并明确待执行。作品集不使用虚构的访谈和数据。”
4:50-5:00 打开证据材料页 “所有 PRD、流程、研究、评测和工作日志可回溯到源码。下一步是执行真实研究和评测，再基于失败证据发布 V2。”

录制验收

  • 录屏中无 API Key、账号、联系人、浏览器历史或未经同意的人脸/声音。
  • 至少演示一次可交互成功与一次模型模式失败回退。
  • 旁白不说“已访谈”“提升”“上线 V2”等没有证据的话。
  • 上传视频后记录链接、日期、源码 commit、环境与是否含真实测试证据。
